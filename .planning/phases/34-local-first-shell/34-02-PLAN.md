<objective>
Make `/study` local-first and keep its cache honest on every grade. The due-card list
paints from IndexedDB before `/api/cards/due` answers, revalidates only when
`/api/version` moves, and is patched in place by the same synchronous code path that
already advances the optimistic study queue.

Purpose: reviews are the only device-originated write that also bumps the server version
counter, but the version bump is useless for the card the user just graded — the phone is
ahead of the server for the length of the fire-and-forget `POST /api/review`. Write-through
at the optimistic-update site is what makes "reopening `/study` never shows the pre-grade
value" true, including offline (D-00 rule 1).

Output: a cache-first `components/StudyClient.tsx` with its own `handleRefresh`, a new
`onReviewCommitted` prop on `components/StudySession.tsx` called from both `submitReview`
and a successful `handleUndo`, and a Playwright spec proving the write-through.
</objective>
