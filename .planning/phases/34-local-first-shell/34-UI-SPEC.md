# Phase 34 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Most of this phase's requirements (LOCAL-01, LOCAL-02, LOCAL-03) are non-visual
plumbing — an IndexedDB read on mount, a version check, and write-through on existing optimistic
updates change *when* data arrives, not *what it looks like*. The populated-state visual design of
Home/Study/Cards/Habits is unchanged and out of scope here (owned by Phase 30/31's UI-SPECs). This
contract covers the genuinely new surface: (1) the background-revalidation indicator (D-01,
LOCAL-01/02), (2) the offline indicator (D-02, LOCAL-05), and (3) pull-to-refresh on 3 new routes
with route-local copy distinct from Home's existing sync copy (D-03/D-04, LOCAL-04).

## Spacing Scale

Declared values (must be multiples of 4) — this is the project's existing scale, confirmed for reuse. No new spacing values are introduced; both new indicators reuse dimensions already established elsewhere in the codebase:

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | Gap between the `WifiOff` icon and "Offline" label inside the offline pill (`gap-1`) |
| sm | 8px | Offline pill internal padding (`px-2 py-1`, matches existing badge conventions e.g. `typeBadgeClass`); gap between icon and text in the background-revalidation pill |
| md | 16px | Not newly used this phase |
| lg | 24px | Not newly used this phase |
| xl | 32px | Not newly used this phase |
| 2xl | 48px | Not newly used this phase |
| 3xl | 64px | Not newly used this phase |

Exceptions: `min-h-11`/`min-w-11` (44px) touch targets — not introduced here (neither new indicator is tappable; both are status-only, non-interactive `role="status"` elements, so no touch-target floor applies to them). Pull-to-refresh reuses `lib/usePullToRefresh.ts`'s existing `PULL_THRESHOLD = 70` / `MAX_PULL = 110` constants verbatim — not a spacing value, not modified by this phase.

**Positioning (new, both indicators use the existing `--nav-height` CSS custom property already published by `components/Nav.tsx`):**
- Background-revalidation pill (D-01): `position: fixed; top: var(--nav-height, 68px)` + `8px` gap below the header, centered — matches the exact `var(--nav-height, 68px)` fallback pattern already established in `components/CardsClient.tsx:1366`. `position: fixed` guarantees zero layout shift regardless of mount/unmount (satisfies D-01's "content itself doesn't flash or shift").
- Offline pill (D-02): lives inside `components/Nav.tsx`'s existing top header row (`max-w-2xl mx-auto px-4 py-3 flex items-center justify-between gap-2`), positioned between the brand link and the settings-gear cluster — no `position: fixed` needed since it's already inside the sticky header; no layout shift because the header row already reserves `gap-2` flex spacing that absorbs its appearance/disappearance without reflowing sibling content width (icon+text pill has a fixed max width, does not grow the header's height).

## Color

No new color tokens. This phase's two new elements draw exclusively from existing `app/globals.css` tokens:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | Page background — unchanged by this phase |
| Secondary (30%) | `var(--surface-1)` / `var(--surface-2)` | Cards, nav, sheets — unchanged by this phase |
| Accent (10%) | `var(--button)` | Unchanged — this phase adds no new accent usage (both indicators are deliberately muted/quiet per D-01/D-02, never drawing the eye like a CTA would) |
| Destructive | existing red tokens | Unchanged — this phase introduces no destructive actions |
| **Background-revalidation pill (D-01)** | `bg-surface-1` (pill background) + `text-muted` (label) + `border border-border` (thin outline, distinguishes it from the page background without a shadow) | Exclusively the "Updating…" transient indicator — never used elsewhere |
| **Offline pill (D-02)** | `bg-surface-3` (chip background) + `text-muted-foreground` (icon + label) | Exclusively the persistent "Offline" indicator in `Nav.tsx`'s header — a deliberately quiet, non-alarming treatment (not red/destructive — going offline is not an error state, it's an informational one, consistent with D-02's framing as "you're looking at saved data," not a failure) |

Accent (`--button`) reserved for — unchanged from prior phases, plus one addition:
- "Add Card" button, Filter icon fill, "Edit" link, Sheet submit buttons (existing, unchanged)
- **New:** the "Try again" retry link on a failed route-local pull-to-refresh (Study/Cards/Habits) or a failed Home sync — reuses the exact existing `text-button font-semibold` retry-link treatment from Phase 31 (`CardsClient.tsx`), not a new color usage

Both new indicators (D-01, D-02) are deliberately **not** colored with `--reward` or `--button` — they are status chrome, not celebratory or actionable elements, and using an accent color there would visually compete with the page's real CTAs (violates the "accent reserved for" discipline every prior phase in this project has held).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — this phase adds no new primary CTA. Pull-to-refresh is a gesture, not a button. |
| Background-revalidation indicator (D-01) | "Updating…" — shown only while the post-mount version-check + (if stale) re-fetch is in flight; disappears the instant it resolves, silently, whether or not new data was found. No distinct "found new data" vs. "already fresh" copy — per D-01, content itself communicates the change (or non-change), the indicator only communicates "a check is happening." |
| Offline indicator (D-02) | "Offline" (persistent pill, `Nav.tsx` header, all 4 routes) — paired with a `WifiOff` icon for a non-text-dependent signal. Disappears the instant `navigator.onLine` flips back to `true`. |
| Pull-to-refresh — Home (unchanged, existing) | "Pull to sync" / "Release to sync" / "Syncing…" — reused verbatim from `components/HomeClient.tsx`; this phase does not change Home's copy, only what happens underneath it (writes through to cache, bypasses version check, per D-04). |
| Pull-to-refresh — Study/Cards/Habits (new, D-04) | "Pull to refresh" / "Release to refresh" / "Refreshing…" — deliberately distinct wording from Home's "sync" copy so the two actions read as different in intent (a lighter, route-local re-fetch vs. a full Google Doc sync), per D-04's locked distinction. |
| Route-local refresh failure (new, Study/Cards/Habits) | "Couldn't refresh. Check your connection and try again." with an inline "Try again" retry link that re-issues the same route-local refresh — mirrors Phase 31's established retry-copy pattern (`Couldn't load more cards. Check your connection and try again.`) for consistency across the app. |
| Home sync failure (unchanged, existing) | "Sync failed — try again from Settings" — reused verbatim from `components/HomeClient.tsx`; not modified by this phase. |
| Empty state — offline, cache exists but is empty (e.g., a brand-new account with zero cards, viewed offline) | Reuses the existing, unchanged empty-state copy for that route (e.g., "No cards yet. Sync your Google Doc to get started." on Cards) — being offline does not change what "no data" looks like; the offline pill (D-02) is the only additional signal. |
| Empty state — offline, no cache has ever been written for this browser (first-ever visit with network off) | Out of scope for this phase's UI (see UI Considerations E1–E4 "empty" rows below) — a cold app-shell launch with zero prior visits and no network requires the service worker precaching Phase 35 ships; this phase's cache-first behavior assumes at least one prior successful online visit populated IndexedDB. |
| Error — background revalidation fetch fails mid-check (device drops offline while "Updating…" is showing) | No error copy — per D-01, the pill simply disappears (same as a successful "no change" outcome); the persistent offline pill (D-02) is what surfaces this state to the user, not a duplicate error message. Two indicators for the same underlying condition would be redundant. |
| Destructive confirmation | Not applicable — this phase introduces no destructive actions. |

## Phase 34 Component Notes

Concrete implementation-facing detail supplementing the tables above.

**1. Background-revalidation pill (D-01), new — mount in each of the 4 `*Client.tsx` shells, driven by that route's own cache-read/revalidation effect (`34-RESEARCH.md` Pattern 1):**
```tsx
{isRevalidating && (
  <div
    role="status"
    aria-live="polite"
    className="fixed left-1/2 -translate-x-1/2 z-[5] flex items-center gap-1.5 bg-surface-1 border border-border text-muted text-xs px-2 py-1 rounded-full shadow-sm"
    style={{ top: 'calc(var(--nav-height, 68px) + 8px)' }}
  >
    <span className="w-1.5 h-1.5 rounded-full bg-muted animate-pulse" aria-hidden="true" />
    Updating…
  </div>
)}
```
`z-[5]` sits below `Nav.tsx`'s `z-10` header/tab bar and below `Sheet.tsx`'s `z-[60]`-class overlays, so it never competes with an open sheet or the nav chrome. `role="status" aria-live="polite"` (not `alert`) matches this project's existing convention for non-urgent transient status (see `Toast.tsx`'s identical choice) — screen readers announce it without interrupting.

**2. Offline pill (D-02), new — mount inside `components/Nav.tsx`'s existing top header row, between the brand link and the settings-gear cluster:**
```tsx
{isOffline && (
  <div
    role="status"
    aria-live="polite"
    className="flex items-center gap-1 bg-surface-3 text-muted-foreground text-xs px-2 py-1 rounded-full shrink-0"
  >
    <WifiOff className="w-3 h-3" aria-hidden="true" />
    Offline
  </div>
)}
```
Requires `Nav.tsx` to own its own `navigator.onLine` + `online`/`offline` listener state (per `34-RESEARCH.md`'s code example) — no prop drilling needed since `Nav.tsx` is already a `'use client'` component with no dependency on route-level state. Import `WifiOff` from `lucide-react` alongside the existing `Home, BookOpen, Layers, Flame, Settings` import.

**3. Route-local pull-to-refresh indicator (Study/Cards/Habits), new — mirrors `HomeClient.tsx`'s existing block exactly, with D-04's distinct copy:**
```tsx
{(pullDistance > 0 || refreshing) && (
  <div
    className="flex items-center justify-center overflow-hidden text-xs text-muted"
    style={{ height: refreshing ? 28 : pullDistance }}
  >
    {refreshing ? 'Refreshing…' : pullDistance >= PULL_THRESHOLD ? 'Release to refresh' : 'Pull to refresh'}
  </div>
)}
```
Wired to each route's own `handleRefresh` (D-04 — never `handleSync`), per `34-RESEARCH.md` Pattern 5.

**4. Route-local refresh-failure copy, new — reuses Phase 31's exact retry-link visual treatment:**
```tsx
<p className="text-center text-sm text-muted">
  Couldn't refresh. Check your connection and try again.{' '}
  <button type="button" onClick={handleRefresh} className="text-button font-semibold">
    Try again
  </button>
</p>
```
