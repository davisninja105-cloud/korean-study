<objective>
Build the cross-process invalidation channel and the in-memory snapshot it gates, so `CardDependency` edges, the `normalizedFront` lemma set, `sessionSize`, and the lessons list can be served without a round trip on the common path — and are provably fresh after any sync, from any of the three writers.

Purpose: STUDY-03. 32-RESEARCH.md verified from source that `scripts/local-resync.mts` never calls `runSync()` and that both standalone scripts run as separate Node processes with their own DB connections — so a `globalThis`-only cache is invisible to two of the three real writers, and a bump placed only in `runSync()` misses the one CLAUDE.md documents as the normal path for bulk syncs. The `Setting` table is the only channel all three share.

Output: `lib/study-cache.ts`, a `studyCacheVersion` Setting key with its single writer, unconditional bumps in both `runSync()` and `relinkAllDependencies()`, and unit coverage for the hit/miss/race/partial-failure paths.
</objective>

| Boundary | Description |
|----------|-------------|
| standalone `tsx` process → Turso | `local-resync.mts` / `relink-dependencies.mts` write the change token from outside the server process; the token row is the only shared state |
