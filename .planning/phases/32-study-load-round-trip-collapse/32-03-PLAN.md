<objective>
Collapse the `/study` load to the measured floor: one physical request for the live pool (carrying the cache-version check as a scalar subquery), one for the chosen cards' full rows, and zero for the four invariant reads on a warm cache.

Purpose: STUDY-01 and STUDY-02. 32-RESEARCH.md verified from installed adapter source that `prisma.$transaction([...])` makes round trips *worse* on this stack (one physical HTTP request per statement plus BEGIN and COMMIT, serialised) while a plain `$queryRaw` pipelines into exactly one — so the collapse is achieved by folding independent reads into single statements, not by transaction batching. STUDY-02 is already resolved as non-duplicative by direct column comparison; this plan keeps both queries and changes only how they execute.

Output: a raw-SQL Phase A gated by the Plan 02 snapshot, a Phase B whose shape is decided by Plan 01's measured verdict, a `{ cards, lessons }` return contract, and a proof that the ordered card sequence did not move.
</objective>
