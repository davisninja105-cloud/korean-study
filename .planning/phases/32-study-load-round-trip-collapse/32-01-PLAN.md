`countingLibsqlClient` takes the object returned by `@libsql/client`'s `createClient` and returns a `Proxy` whose `get` trap increments a module-scope physical counter when the accessed property is `execute`, `batch`, or `transaction`, then returns the real member via `Reflect.get`. Rationale, stated in a header block comment: `@prisma/adapter-libsql` 7.6.0 routes every statement through the underlying client's `execute()`/`batch()`, and for the HTTP (Turso) transport each of those is exactly one physical HTTP request — so counting at this boundary, before the adapter wraps the client, is the ground-truth physical count. `getQueryCounts()` returns `{ physical, prismaEvents }`; `resetQueryCount()` zeroes both. `notePrismaQueryEvent()` increments the second counter, and is the sink `lib/prisma.ts` wires `$on('query')` into.

Follow this repo's JSDoc-header convention for single-source-of-truth modules (see `lib/sequence.ts` and `lib/card-key.ts`): the header must state the counting definition, why the Proxy sits under the adapter rather than over it, and that the module is dev/test instrumentation that is inert unless `STUDY_QUERY_COUNTER` is `1`.
