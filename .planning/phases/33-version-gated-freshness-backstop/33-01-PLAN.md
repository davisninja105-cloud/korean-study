<objective>
Ship the version counter end-to-end: one write path (a review) moves a `dataVersion`
Setting row, `GET /api/version` serves it, and `FreshnessWatcher` consults it before
deciding whether to re-fetch the route payload. Then widen the write side to cover
sync completion and lock down what must NOT move the counter.

Purpose: the freshness backstop currently delivers the same payload twice on every
resume. Narrowing the JSON half of that dual delivery behind a cheap counter makes the
common "nothing changed" resume cost one tiny Setting-row read instead of a full
`/api/cards/due` / `/api/cards` / `/api/activity`+`/api/stats` fetch — without removing
the backstop, which still guards a real unfixed Next.js 16.2.1 bug.

Output: `app/api/version/route.ts`, `getDataVersion()`/`bumpDataVersion()` in
`lib/settings.ts`, a tx-scoped bump in `POST /api/review`, an unconditional-refresh +
version-gated backstop in `components/FreshnessWatcher.tsx`, a bump call in
`runSync()`, and two test files proving both sides of the gate.
</objective>
