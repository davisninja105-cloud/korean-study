<objective>
Make the e2e freshness harness tell the truth under the new version gate.

Purpose: all four `e2e/freshness-*.spec.ts` files simulate "the server changed" by
writing directly through Prisma in a `tsx` subprocess — never through `POST /api/sync` or
`POST /api/review`. Once plan 33-01's gate lands, those direct writes no longer move the
counter, so the backstop's JSON delivery never fires in any of them. Most specs would
stay green while silently no longer proving what they exist to prove, and one
(`freshness-fresh-paths.spec.ts`'s Upsert-not-replace extension) would stop reaching its
mocked interception entirely. This plan closes both, and adds a deterministic lock so a
future regression that stops the bump turns a test red instead of hollow.

Output: a `dataVersion` bump inside the three freshness mutators, two new harness
helpers, a version-advancing call at the one spot the fresh-paths spec needs it, and a
non-vacuity lock in the gate spec.
</objective>
