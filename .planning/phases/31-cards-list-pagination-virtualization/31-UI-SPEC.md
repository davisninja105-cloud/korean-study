# Phase 31 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

**Visual hierarchy (checker-flagged addition):** unchanged from today's `/cards` page. The sticky
search bar + "Add Card" button remain the primary visual anchor (top of viewport, always visible);
the Filter icon + active-filter badge is the secondary control. Card rows and their grouped
sections are the content below that anchor — populated-state visual design is untouched by this
phase (see `## UI Considerations` → populated rows). This phase's new elements (skeletons, loading
captions, retry links) are visually subordinate — small, muted (`text-muted`), inline with the
content they describe — never competing with the search bar / Add Card anchor for attention.

| Property | Value |
|----------|-------|
| Tool | none — existing hand-rolled semantic-token system in `app/globals.css` (established v1.1 "Design System Tokens & Sweep"). shadcn is **not** initialized here: `components.json` is absent, the project has a mature bespoke component set (`Sheet.tsx`, `SwipeRow.tsx`, `HighlightedSentence.tsx`, etc.), and `CLAUDE.md` explicitly forbids literal color utilities in favor of the token system. Introducing shadcn now would contradict established project conventions and is unrelated to this phase's goal (pagination/virtualization performance). |
| Preset | not applicable |
| Component library | none (bespoke React components) |
| Icon library | `lucide-react` (already a dependency; `SlidersHorizontal` used today) |
| Font | `'Pretendard Variable'` (Korean, via `--font-korean` / `.hangul` utilities) + Geist Sans (`--font-sans`, UI chrome/English) |

## Spacing Scale

Declared values (must be multiples of 4) — matches the scale already in use across `CardsClient.tsx`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, skeleton bar gaps |
| sm | 8px | Compact element spacing (`gap-2`), group header gaps |
| md | 16px | Default element spacing (`p-4` card rows, `gap-4` page sections) |
| lg | 24px | N/A — not used in existing Cards page; no new use introduced here |
| xl | 32px | N/A — not introduced by this phase |
| 2xl | 48px | N/A — not introduced by this phase |
| 3xl | 64px | N/A — not introduced by this phase |

Exceptions: `min-h-11` / `min-w-11` (44px) touch targets — existing project-wide convention for tap targets (Filter icon button, Edit link, grade/segment buttons); 44 is a multiple of 4 so this is not a true scale exception, just called out because it's a fixed floor, not a spacing gap.

New elements this phase adds (all reuse the existing scale, no new spacing values):
- Skeleton card row: same `p-4` container padding as a real card row (visual continuity — the skeleton must occupy the exact footprint of the row it stands in for, preventing layout shift when real data replaces it).
- Infinite-scroll sentinel: `h-px` (1px, effectively 0) — invisible, spacing-neutral trigger element positioned after each group's last loaded row. **Exception (checker-flagged):** this is a technical `IntersectionObserver` trigger target, not a visible spacing value — it renders no content and occupies no perceptible layout space, so it is excluded from the 4px-multiple spacing scale by design, the same way `min-h-11` is called out above as a floor rather than a gap.
- Inline search-loading spinner: `gap-2` from the search input's trailing edge (sits inside the sticky bar's existing `gap-2` flex row).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` (`#f9fafb` light / `#0b0f1a` dark) | Page background behind the whole `/cards` scroll area |

| Accent (10%) | `var(--button)` (`#3b82f6` blue) | See reserved-for list below — unchanged from existing page, no new accent usage introduced |
| Destructive | Tailwind `red-500` / dark `red-400` | Swipe-to-delete reveal (existing `SwipeRow`), "Clear all filters" link (existing) — no new destructive actions in this phase |

Accent (`--button`) reserved for — explicit list, matches existing page + this phase's new elements:
- "Add Card" button (existing)
- Filter icon fill + active-filter-count badge when filters are active (existing)
- "Edit" link on each card row (existing)
- Active filter pill in the Filter Sheet (existing)
- "Done" button in Filter Sheet, submit button in Add/Edit sheets (existing)
- **New:** the inline search-loading spinner (reuses the exact existing spinner pattern: `border-2 border-button border-t-transparent rounded-full animate-spin`, seen today in `AudioButton.tsx`, `GlossProvider.tsx`, `HistoryClient.tsx`)
- **New:** "Try again" retry link text color, on a failed batch-load or failed search request

`--skeleton-bg` (`bg-skeleton`, shipped Phase 30) reserved for:
- **New:** skeleton card rows on `/cards` initial load and on Reading practice initial load (same token, same `animate-pulse`, matching the Phase 30 pattern already used elsewhere — do not invent a new gray)
- **New:** skeleton rows appended during infinite-scroll batch loading (same token, smaller count)

No new color values are introduced. Every new element in this phase draws exclusively from tokens already defined in `app/globals.css`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Add Card" (unchanged from existing — this phase does not add a new primary CTA; there is deliberately **no** "Load more" button per D-03, auto-load replaces it) |
| Empty state — no cards at all | "No cards yet. Sync your Google Doc to get started." (unchanged, existing copy) |
| Empty state — search active, zero matches | "No results for "{query}"." (new — more specific than today's generic "No cards match your search."; surfaces the actual query so the user can see what was searched, important now that search runs server-side across the full ~1056-card deck rather than filtering an in-memory page) |
| Empty state — lesson-range/type filter active (no search), zero matches | "No cards match this filter." (new — distinguishes filter-caused emptiness from search-caused emptiness so the user knows which control to change) |
| Empty state — Reading practice, filtered to zero sentences | "No example sentences match your filter." / "No example sentences yet. Sync a lesson to generate them." (existing wording pattern, extended to the new independent Reading practice fetch) |
| Loading — initial page load | No text; skeleton rows only (per Phase 30's visible-skeleton convention — skeletons communicate loading, no redundant caption needed) |
| Loading — infinite-scroll batch in flight | "Loading more…" (new, `text-xs text-muted`, appears below the last loaded row of the group currently fetching, above the skeleton rows) |
| Loading — search request in flight (debounced) | "Searching…" (new, small inline spinner + text, appears next to/below the sticky search input; existing rows stay visible and dim to `opacity-60` rather than disappearing, avoiding a blank flash between keystroke-settled and results-arrived) |
| End of list | "You've reached the end." (new — shown once a group's server-reported total count equals its loaded count; muted, centered, `text-xs`) |
| Error — batch load fails (network/server error mid-scroll) | "Couldn't load more cards. Check your connection and try again." with an inline "Try again" retry link that re-issues the same page request (new) |
| Error — search/filter request fails | "Couldn't search right now. Try again." with an inline "Try again" retry link (new) |
| Error — Edit sheet fails to fetch a card's sentences | "Couldn't load this card's sentences. Try again." with an inline "Try again" retry link inside the sheet, above the (otherwise sentence-less) edit form (new — required because sentences move to an on-demand fetch, see Claude's Discretion in CONTEXT.md) |
| Destructive confirmation | Delete card: existing native `confirm('Delete this card?')` via `SwipeRow` — unchanged, not in scope for this phase |
