  <name>Task 1: Debounced search input with a stale-response guard</name>
  <reversibility rating="reversible">A hand-rolled hook behind a stable call site — trivial to swap for
  a library debounce later if ever needed.</reversibility>
  <read_first>lib/usePullToRefresh.ts (existing hand-rolled hook precedent),
  .planning/phases/31-cards-list-pagination-virtualization/31-RESEARCH.md (Code Examples —
  useDebouncedValue), components/CardsClient.tsx</read_first>
  <files>lib/useDebouncedValue.ts, components/CardsClient.tsx</files>
  <behavior>
    - `useDebouncedValue(value, 300)` returns `value` unchanged when called with a stable value that
      hasn't changed since the last render (no timer fires if nothing changed).
    - When `value` changes twice within 300ms, the hook only ever settles on the SECOND value — the
      first intermediate value is never returned (proves debounce collapses bursts, not just delays).
    - The timer is cleared on unmount / on each new value (no stale `setDebounced` call fires after a
      newer value has superseded it) — verified via fake timers.
  </behavior>
  <action>
  Create `lib/useDebouncedValue.ts`: `export function useDebouncedValue<T>(value: T, delayMs: number):
  T` — `useState` seeded with `value`, a `useEffect` that `setTimeout(() => setDebounced(value),
  delayMs)` and returns a `clearTimeout` cleanup, dependency array `[value, delayMs]`. No `Date.now()`/
  `Math.random()` in render (react-hooks/purity).

  In `components/CardsClient.tsx`, wire the existing search `<input>`'s `search` state through
  `const debouncedSearch = useDebouncedValue(search, 300)`. Add a `useEffect` keyed on
  `[debouncedSearch, filter, lessonFrom, lessonTo]` that re-fetches every currently-relevant group's
  first page from `GET /api/cards` with the new params (search-active mode fetches one flattened
  `type=all` page instead of four per-group pages — see Task 3). Guard against stale/out-of-order
  responses with a request-sequence ref: increment a `useRef<number>(0)` counter before each fetch,
  capture its value in the closure, and only apply the response if the captured value still equals the
  ref's current value at resolution time (a strictly later request will have advanced the ref past the
  captured value, so an earlier response arriving late is silently discarded rather than overwriting
  newer results — this is the CARDS-03 stale-response prohibition's concrete mechanism).
  </action>
  <verify>
    <automated>npx vitest run tests/use-debounced-value.test.ts</automated>
  </verify>
  <done>`lib/useDebouncedValue.ts` exists with passing behavior tests; the search input in
  `CardsClient.tsx` triggers a server refetch ~300ms after typing settles, and a manually-simulated
  out-of-order response (older request resolving after a newer one) never overwrites the newer results.</done>
