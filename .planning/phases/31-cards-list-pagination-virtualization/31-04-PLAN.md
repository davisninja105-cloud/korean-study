<objective>
Close the three remaining integration gaps 31-01/31-02/31-03 deliberately left open: wire the Reading
Practice tab to its own independent endpoint (D-07/D-08, replacing 31-01's temporary interim), wire the
Edit sheet's on-demand sentence fetch (`GET /api/cards/[id]`) so `CardEditor` works again now that
sentences are gone from the list query, and fix `FreshnessWatcher`'s `/cards` backstop merge strategy
(replace → upsert-by-id) now that `GET /api/cards` returns a partial page instead of the full deck.
Finish by measuring the real post-migration `/cards` performance and tightening `e2e/perf.spec.ts`'s
budget from a genuine number, then running the full regression suite.

Purpose: these three gaps are all instances of the same root cause — code that assumed `/cards`' data
source was the full, unbounded deck now needs to handle a partial, paginated one. Left unfixed, each is
a silent data-loss or broken-feature bug, not a missing feature.

Output: Reading Practice and the Edit sheet fully functional against the paginated backend;
`FreshnessWatcher` upsert-safe; `e2e/perf.spec.ts`'s `/cards` budget tightened from real measurements;
full `npm test` + relevant e2e suites green.
</objective>
