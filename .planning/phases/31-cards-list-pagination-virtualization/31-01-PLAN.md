<objective>
Replace `/cards`' single unbounded `prisma.card.findMany()` (the ~1056-card, ~1616-sentence-row query
identified as the milestone's largest remaining cold-path cost) with a cursor-paginated, sentence-free
data layer, and prove the new shape end-to-end by rendering the Vocabulary type-group through a real
DOM-bounded virtualized list (`react-virtuoso`). This is the phase's leading tracer: DB query shape,
API contract, RSC initial render, and client rendering are all real and production-quality by the end
of this plan for one group; the remaining three groups, search, lesson filtering, and Reading Practice
are expansion work in later plans of this same phase.

Purpose: CARDS-01 requires the initial `/cards` query to be capped and sentence-free; CARDS-03 requires
search/filter to run server-side against the full deck. Both need the same `getCardsPage`/`where`-builder
foundation this plan builds — establishing it correctly and generically (not per-group hardcoded) here
avoids rework in the plans that consume it.

Output: `lib/cards-list.ts` rewritten with `getCardsPage()`/`getCardsGroupCounts()`; `GET /api/cards`
accepting query params; `app/cards/page.tsx` and `components/CardsClient.tsx` updated so the Vocabulary
group renders a real capped, virtualized page on load; `react-virtuoso` installed (behind a
`checkpoint:human-verify` per the SUS package-legitimacy note); unit tests for the new data layer.
</objective>
