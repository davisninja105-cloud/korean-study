<objective>
Close UAT gap G-31-2 (31-UAT.md Test 2, D-08): on mobile, the Cards/Reading Practice segmented toggle has
no sticky positioning at all and scrolls out of reach once a user scrolls down within a virtualized
group's list — Phase 31's auto-loading of hundreds of rows made this pre-existing structural gap (present
since before Phase 31, per .planning/debug/sticky-headers-scroll-away-mobile.md) a routinely-triggered
blocker instead of a rare edge case. Fix both defects the debug session diagnosed: (1) the view-toggle
`<div>` in components/CardsClient.tsx has no sticky class, so it scrolls away independently of the sticky
search bar above it; (2) CardsClient's sticky search bar and Nav.tsx's persistent header both use `top-0`,
so once both are pinned they visually collide instead of stacking.

Purpose: without this fix, a mobile user who scrolls even partway down the Vocabulary group cannot reach
Reading Practice (or back to Cards) without first scrolling all the way to the top — a routine, blocking
workflow break discovered during Phase 31's own UAT session (test 2: "this isn't possible on mobile, the
Reading Practice and Cards headers disappear when you scroll").

Output: components/Nav.tsx exposes its real rendered header height as a `--nav-height` CSS custom
property; components/CardsClient.tsx merges the search bar and view-toggle into one sticky unit offset by
that value; a new Playwright regression spec proves both the toggle-reachability fix and the Nav-overlap
fix on a short mobile-width viewport.
</objective>
