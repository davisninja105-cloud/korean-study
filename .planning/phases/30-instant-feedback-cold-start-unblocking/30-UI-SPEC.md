## Color

This phase's central visual deliverable is a **new semantic token**, not a change to the existing 60/30/10 page composition (which is untouched):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` | Page background — unchanged by this phase |
| Secondary (30%) | `var(--surface-1)` / `var(--surface-2)` | Cards, nav, sheets — unchanged by this phase |
| Accent (10%) | `var(--button)` | Unchanged by this phase — not touched |
| Destructive | existing red tokens | Unchanged by this phase — not touched |
| **New: Skeleton** | Light `#f3f4f6` (= current `--surface-3` light value) · Dark `#1c2030` (= current `--surface-1` dark value) | **The entire visual payload of this phase.** Used exclusively by loading-state placeholders — never by any populated/interactive/decorative surface. |

Accent reserved for: unchanged from prior phases — `var(--button)` stays reserved for primary CTAs and interactive affordances only; this phase does not add, remove, or reassign any accent usage.

**`--skeleton-bg` token contract (D-01–D-03, locked):**
- New, isolated CSS variable — deliberately **not** a reuse or raise of `--surface-3`. Dark `--surface-3` (`#0b0f1a`) currently equals dark `--background` (`#0b0f1a`), which is exactly why today's skeletons are invisible in dark mode — and `bg-surface-3` has 17+ non-skeleton consumers (`Nav.tsx` hover, `Toast.tsx`/`GlossProvider.tsx` close buttons, `ProficiencyArc.tsx` track, `HabitTracker.tsx` empty cells, `CardEditor.tsx` cancel hover, `Sheet.tsx`, `HabitHeatmap.tsx`, `AudioButton.tsx`, `ModeSelector.tsx`, and more) that must NOT change appearance in this phase.
- Dark value: `#1c2030` (reuses the existing `--surface-1` dark shade — already proven legible against `#0b0f1a`).
- Light value: `#f3f4f6` (reuses the existing `--surface-3` light shade — light mode wasn't broken, but unifying onto one token avoids per-theme branching in every `loading.tsx`).
- **Must be defined in all 3 required blocks of `app/globals.css`:** the light default in `:root`, the dark value in `@media (prefers-color-scheme: dark) { :root { ... } }`, AND the dark value again in `:root[data-theme="dark"]` (the manual-toggle override block) — these last two must be byte-identical, per the project's established dark-token-mirroring rule (also flagged as a Phase 30 blocker in STATE.md).
- Exposed as a Tailwind utility via `@theme inline` the same way `--color-surface-3` is today: `--color-skeleton: var(--skeleton-bg);` → generates `bg-skeleton`.
- **Consumers to migrate from `bg-surface-3` to `bg-skeleton`** (exhaustive list — nothing outside this list changes):
  - `app/study/loading.tsx` (all 3 placeholder divs)
  - `app/cards/loading.tsx` (all placeholder divs, including the 5 repeated card-row skeletons)
  - `app/habits/loading.tsx` (all placeholder divs)
  - `app/history/loading.tsx` (all placeholder divs)
  - `components/StudyClient.tsx` — the two inline `animate-pulse` skeleton blocks at `phase === 'loading'` (~line 237–241) and `phase === 'loading-practice'` (~line 348–353); NOT the `isFilterLoading` skeleton, which is new markup per D-04 below and is built with `bg-skeleton` directly (no migration — it doesn't exist yet).
  - Every other `bg-surface-3` usage in the codebase (`Nav.tsx`, `Toast.tsx`, `GlossProvider.tsx`, `ProficiencyArc.tsx`, `HabitTracker.tsx`, `CardEditor.tsx`, `Sheet.tsx`, `HabitHeatmap.tsx`, `AudioButton.tsx`, `ModeSelector.tsx`, etc.) is explicitly **left unchanged**.

**PWA manifest colors (PERCEPT-02, locked by ROADMAP.md wording — not discretionary):**
- `app/manifest.ts`'s `background_color` (currently `'#f9fafb'`, light) and `theme_color` (currently `'#3b82f6'`, button blue) must both change to `'#0b0f1a'` — the exact dark value already declared as the dark entry in `app/layout.tsx`'s `viewport.themeColor` array (`{ media: '(prefers-color-scheme: dark)', color: '#0b0f1a' }`) and as the dark `--background` value in `globals.css`.
- Rationale: `background_color` paints the PWA splash/launch screen before any CSS loads — it is a single static value with no light/dark media-query variant in the manifest spec, so matching it to the app's actual dark chrome (rather than the current light default) is what eliminates the white flash on cold launch (Success Criterion 2). `theme_color` follows suit for status-bar/task-switcher consistency.

## Phase 30 Component Notes

Concrete implementation-facing detail supplementing the tables above:

**1. `--skeleton-bg` token (D-01–D-03):** add to `app/globals.css` in all 3 required locations (light `:root`, dark `@media` block, dark `:root[data-theme="dark"]` block) and to the `@theme inline` block (`--color-skeleton: var(--skeleton-bg);`). See the Color section above for exact values and the full consumer migration list.

**2. Lesson-filter skeleton (D-04), replacing `StudyClient.tsx`'s `isFilterLoading` branch (~line 269–272):**
```
Current (to be replaced):
  <div className="h-16 flex items-center justify-center" role="status" aria-label="Loading cards">
    <Loader2 className="w-5 h-5 animate-spin text-muted" />
  </div>

Target shape (exact layout match to the real content it precedes, ~line 300–316):
  <div className="flex flex-col items-center gap-6 py-6" role="status" aria-label="Loading cards">
    <div className="h-16 flex flex-col items-center justify-center gap-1">
      {/* bar 1: stands in for the text-5xl font-bold due-count number */}
      <div className="h-12 w-16 rounded-lg bg-skeleton animate-pulse" />
      {/* bar 2: stands in for the "card(s) ready" label */}
      <div className="h-4 w-24 rounded bg-skeleton animate-pulse" />
    </div>
    {/* button placeholder: stands in for "Start studying →" */}
    <div className="w-full max-w-sm min-h-14 rounded-2xl bg-skeleton animate-pulse" />
  </div>
```
Exact bar widths/heights above are a reasonable default, not locked — CONTEXT.md leaves exact pixel sizing to implementation discretion; the locked constraints are: (a) two bars in the count slot, one positioned where the number goes and one where the label goes, (b) both live inside the unchanged `h-16` slot, (c) the button placeholder matches the real button's `min-h-14 rounded-2xl` exactly, (d) nothing shifts position when real content swaps in — the wrapping `flex flex-col items-center gap-6 py-6` container must be identical between skeleton and real states. Remove the now-unused `Loader2` import if nothing else in the file still uses it.

**3. `app/manifest.ts`:** change `background_color: '#f9fafb'` → `'#0b0f1a'` and `theme_color: '#3b82f6'` → `'#0b0f1a'`. No other manifest fields change.

**4. Root layout / settings (LAYOUT-01 visual truth only — mechanism is not a UI-SPEC decision):** whatever mechanism plan-phase selects for making `RootLayout` synchronous, the rendered result must be indistinguishable, on the very next navigation after a settings save, from today's `await`-based version — no flash of `--button`/`--reward` defaults, no flash of unscaled reading text, no flash of the reading-aid class toggling after paint.
