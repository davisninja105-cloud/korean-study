Create `scripts/sw-runtime.mjs` as a plain Node ESM module holding only pure functions, no browser globals at module scope, so Vitest can import it directly and `scripts/gen-sw.mjs` can inline its source text into the generated worker. Export the constant `SHELL_CACHE_PREFIX` with the value `ks-shell-`; the constant `NAVIGATION_ROUTES` listing `/`, `/study`, `/cards`, `/habits`; a function `routeStrategy({ mode, sameOrigin, pathname })` returning the string `passthrough` when `sameOrigin` is false, `navigate` when `mode` equals `navigate`, `network-only` when `pathname` starts with `/api/`, and `cache-first` otherwise — evaluated in exactly that order; and a function `staleShellCacheKeys(allKeys, currentCacheName)` returning every key that starts with `SHELL_CACHE_PREFIX` and is not strictly equal to `currentCacheName`.

Create `scripts/sw-template.js` holding the worker's event handlers with three substitution tokens: `__SW_RUNTIME__` (where the inlined runtime source lands), `__CACHE_NAME__`, and `__PRECACHE_LIST__`. The `install` handler passes the whole precache write to `event.waitUntil` so an interrupted install never activates a half-populated cache, opens `CACHE_NAME` and adds every precache-list URL. Deliberately do not self-activate in `install` — the worker must wait (D-08). The `activate` handler deletes every key `staleShellCacheKeys` reports, then claims clients. The `fetch` handler builds a `URL` from `request.url`, computes `sameOrigin` against `self.location.origin`, calls `routeStrategy`, and dispatches: `passthrough` returns without calling `respondWith`; `navigate` fetches from network, clones a successful response into the cache under a pathname-normalized key (query string dropped) and returns it, falling back on rejection to a cache match for that normalized key; `network-only` responds with a bare network fetch and no cache fallback, so an offline `/api/*` failure still reaches the page as a real network error; `cache-first` responds with a cache match, else fetches, clones into the cache, and returns. The `message` handler activates the waiting worker only for a payload whose `type` is `SKIP_WAITING`.

Create `scripts/gen-sw.mjs` as a plain Node ESM script following `scripts/gen-icons.mjs`'s conventions (`node:fs`/`node:path` only, no TypeScript, no project imports). Export three pure helpers so `tests/gen-sw.test.ts` can drive them without touching the real build tree: `resolveBuildId(env)` returning `env.VERCEL_GIT_COMMIT_SHA`, else `env.VERCEL_DEPLOYMENT_ID`, else the literal `local-dev` — the same fallback chain `app/api/version/route.ts` already uses, so the worker's cache name and Phase 34's IndexedDB namespace move together on every deploy; `collectPrecacheList(staticDir, shellAssets)` which walks `staticDir` recursively via `readdirSync` with the `recursive` option, keeps only real files, maps each to a `/_next/static/`-prefixed POSIX URL, concatenates `shellAssets`, and returns the result sorted with a plain lexicographic comparator; and `renderServiceWorker({ runtimeSource, template, cacheName, precache })` which strips the leading `export ` keyword from each exported declaration in `runtimeSource` and substitutes it plus the JSON-stringified cache name and precache array into the template's three tokens. The shell-asset list is `/fonts/PretendardVariable.woff2`, `/icon-192.png`, `/icon-512.png`, `/icon-512-maskable.png`, `/apple-icon.png`, and `/manifest.webmanifest`. Unlike `scripts/gen-icons.mjs`, whose PNG output is committed because it changes only when the source SVG is edited, this output changes on every single deploy — add `/public/sw.js` to `.gitignore` under a comment naming it as build-generated.

Export `registerServiceWorker(onUpdateAvailable)` which returns immediately unless `process.env.NODE_ENV` is `production` and `serviceWorker` is present on `navigator` — the environment gate matters because Turbopack's dev server rewrites chunk contents behind stable URLs, and a cache-first worker in dev would mask live edits. Register `/sw.js`, and on the registration's `updatefound` event attach a `statechange` listener to the installing worker that invokes `onUpdateAvailable` once the worker reaches `installed` while `navigator.serviceWorker.controller` is already set — that combination is precisely an update rather than a first install. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service worker → origin server | Worker-initiated fetches (script update, install-time precache, runtime fills) carry the session cookie and can be redirected by `middleware.ts` |
| service worker cache → page | Cached responses are replayed to the page with no revalidation |
| page → service worker | The `postMessage` control channel that can trigger activation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-35-01 | Tampering | `middleware.ts` matcher / `/sw.js` and `/fonts/*` fetches | high | mitigate | Task 1 adds `sw\.js` and `fonts/.*` to the matcher's negative-lookahead alternation, so an expired-session update fetch returns the real asset instead of a login redirect (a redirected HTML response fails worker registration outright and poisons the precache under a JS key) |
| T-35-02 | Spoofing | install-time route-document warm in `scripts/sw-template.js` | high | mitigate | Task 2 stores a warmed navigation only when the response is ok *and* its final URL's pathname equals the requested route, so a login redirect is never cached under an app route key and replayed offline as that route |
| T-35-03 | Tampering | `message` handler in the generated worker | low | accept | The worker message channel is same-origin by browser guarantee; the handler acts only on the activation payload and performs no privileged work beyond activating the already-installed worker |
| T-35-04 | Information Disclosure | shell cache persisting authenticated route HTML after session expiry | medium | accept | Inherited, unchanged risk from Phase 34's accepted client-cache posture: single-tenant, single shared password, no PII beyond personal Korean study data; the same data class already persists unencrypted in Phase 34's IndexedDB route cache |
| T-35-05 | Denial of Service | precache size at install | low | accept | Research measured `.next/static/` at 1.1 MB across 25 files; a quota-exhausted install fails closed, leaving the previous worker active and serving |
| T-35-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no new package — `idb` was already audited in Phase 34 and the generator uses only Node builtins. If any task here would add a dependency, a blocking human checkpoint per the package-legitimacy gate is required first for any `[ASSUMED]`/`[SUS]` package; `[SLOP]` packages are forbidden |
